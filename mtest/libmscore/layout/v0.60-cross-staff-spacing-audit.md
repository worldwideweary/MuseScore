# v0.60: cross-staff spacing integration boundary

Target: the pinned Studio 4.7.5 horizontalspacing source, following the broader
v0.43 audit. The user reports v0.59 mtests passing; natural and justified S1
look close to the supplied 4.7.5 captures. Cross-staff remains explicitly

still run in the fallback. Do not describe that fallback as complete parity.

## Source rules and current coverage

| Studio function | Responsibility | Evolution integration boundary |
| --- | --- | --- |
| `checkCollisionsWithCrossStaffStems` | Space against a preceding same-beam stem as effectively infinite in height when its final vertical position is unknown but the beam arrangement proves a crossing. | `Chord::shape` deliberately omits stems for moved/cross-staff beamed chords. Merely accepting the remaining rectangles would lose this constraint. |
| `computeCrossBeamSpacing` / `applyCrossBeamSpacingCorrection` | Determine stem-side transitions, signed notehead/stem displacement, opposing beamlet clearance, forbidden cross-staff kerning and minimum stem spacing. | `crossBeamSpacingOffset4` in measure.cpp and the opt-in segment kerning path cover restricted ordinary cases. The planner rejects their nonzero native width offset and does not yet reproduce the complete rule. |
| `minStemDistOnNonAdjacentCross` | Constrain adjacent chords on one cross-staff beam even when another voice inserts intervening segments. | The planner's lookback machinery exists, but this beam-specific constraint is not connected. |
| `spaceSegments` | Apply the cross-beam correction to natural chord/rest width before placement. | The new planner must account for fixed signed displacement separately from rhythmic spring growth. Applying a native offset and a new correction together would double-count it. |
| segment `minHorizontalDistance` | Add cross-stem constraints to per-staff geometric distances, including nonadjacent beam checks. | The typed collision kernel handles known rectangles. It needs an explicit cross-staff constraint layer, not guessed stem rectangles in the global native Shape. |

The pinned source calls cross-beam correction during `spaceSegments`,
cross-staff stem collision checks from segment distance, and the nonadjacent
stem rule near the end of that same distance function. Final beam layout and
spacing do not form one interchangeable pass. Evolution's earlier stem-side
inference is deliberately bounded because its initial stem directions can be
provisional. Preserve that restriction until equivalent context is available.

- `v0.60-spacing-cross-staff.mscx`

track 4 holds C3 for the whole measure. There are no rests, accidentals,
tuplets, manual offsets or explicit beam-position overrides. Both experimental

the separate R1 rest-position discrepancy with horizontal integration.

the intended durations, onset sequence, moved notes and actual cross-staff
beam; finite spacing; repeat layout; and restoration with spacing off. It
requires the known cross-staff/width-offset rejection and verifies that a
failed plan leaves output and live positions untouched. These are fallback
controls, not acceptance tests for modern cross-staff placement yet.

## v0.61 WIP: read-only context prepared

`buildCrossStaffContext4` in spacingplan4.cpp now builds the first bounded
description, published only after every input passes. Its borrowed chord
entries record visual staff and inferred effective stem side; pair entries
record whether a signed displacement is allowed, the fixed displacement and
the corresponding minimum-width floor. Nothing writes note, chord, beam,
segment or measure layout data. The production planner still rejects these
scores; the description is not connected to placement yet.

Eligibility is deliberately narrower than the earlier fallback: one prepared
automatic cross-staff beam, at least three single-note eighths in one measure,
one contiguous track, two adjacent visible pitched five-line staves, full-size
normal noteheads and no forced stem direction/manual beam edit. The within-
staff note-line bounds make staff-side inference unambiguous. Rest, tuplet,
grace, tremolo, independent beamed companion and unsupported decoration
contexts are rejected. Unbeamed chord companions are retained as constraints;
an outgoing longer value allows adjustment, while a companion at the next
onset blocks it, following the pinned source rule.

For a lower-to-upper (up-to-down) transition, the floor includes both twice
the notehead/stem displacement and notehead width plus source stem padding.
Eighth-note-only eligibility avoids claiming opposing secondary-beamlet
coverage. Same-staff pairs receive no cross-beam offset. All pair descriptors
remain inputs for later geometric and spring integration, not final segment
distances.

X1's existing boundary test now also requires successful context construction
under both beam settings, alternating inferred sides, the expected -/+/− fixed
offsets, and unchanged live positions/stem directions. Forced stem direction
must reject without overwriting a sentinel output. Existing planner rejection
and repeat/off restoration assertions stay intact. No new screenshots are
needed for this WIP stage; rendering is unchanged.

Next add the explicit stem-constraint geometry and fixed-offset reconstruction
using this context. Only then replace X1's planner-rejection assertions with
full-plan/actual-application checks. Do not remove the production guard first.
