# v0.150 WIP: read-only musical-input collector

Base: v0.149 43b2a66. First implementation step of audit package A.

Add spacinginput4.h/.cpp to the core build. Collect normal chord/rest anchors,
every before/after-grace member in accessor musical order, per-track ordinals,
exact raw slur endpoints and reverse per-anchor slur indices. Capture note tie
and note-spanner attachment pointers as separate metadata. Record direction
requests and the observed cached up flag separately; do not call that flag
an authoritative AUTO result. Unresolved endpoints remain explicitly missing
or unindexed rather than invoking lazy anchor computation.

The public view exposes const entries; all pointers are borrowed for one
preparation pass and must be discarded before score mutation. Build a pending
view and assign only on success. Structural ownership/duplicate errors fail
atomically; no first-grace, slur-count, direction, line-style, feature, staff-
move or same-measure whitelist decides whether valid metadata is collected.
No layout, styles, selection, undo history or native shape cache is changed.

This prototype is intentionally not consumed by the runtime spacing planner
in this stage. It creates the general attachment/musical-order seam; direct
producer geometry, authoritative direction preparation and policy consumers
are subsequent package-A work. It neither fixes the start-anchor spacing
transition nor claims a speed improvement yet.

## Focused native acceptance tests

Add four spacingInputSnapshot4 data rows using existing one/two-system grace,
tie/rest and note-spanner/rest fixtures. No new visual fixture is required.
Use actual nextChordRest navigation as an independent oracle for every track's
order. Require direct anchor/note/slur lookup identities, preserved tie and
note-spanner metadata, endpoint-to-anchor reverse indices and unchanged layout
positions/beam geometry/slur grips/shapes, selection, styles, command state and
undo history after collection. Null-score failure preserves the prior output.

An intentionally unresolved root slur stays unresolved after capture: no
startCR/endCR lazy computation is permitted. In the grace rows, execute real
Shift+Right on the START grip, discard the old view before editing, then build
a fresh view. Require the new exact grace identity and next per-track ordinal
even though the tick is unchanged. Undo restores the captured original
identity. The test does not require the known spacing transition to disappear
before any runtime consumer has been changed.

## Next package-A integration

The collector is score-wide and pass-scoped. Do not call it per pair or per
candidate prefix, and do not retain it across edits. Future range/system views
must share an appropriate preparation context rather than introducing another
whole-score query inside the inner loop. Anchor, note and slur lookup maps
avoid repeated full-score scans for consumers.

Remaining before runtime integration: authoritative direction preparation,
per-item geometry emission, an explicit shared preparation context and general
attachment policy consumers. The current eligibility whitelist, hybrid fallback
and start-anchor spacing change are deliberately still present. This completes
the first musical-metadata seam, not all of package A or the architectural
consolidation. Next: connect prepared attachment queries to a general policy
consumer in isolation while retaining specialized curve bounds separately.
