# v0.89: prepare grace-beam shapes before horizontal spacing

## Native evidence

The v0.88 report isolates the discrepancy to A3's first chord-rest segment
(tick 3840): applied width 190.65956323818887 versus reconstructed natural
width 186.52123523622049. Other segment widths agree within floating-point
precision. Both beam modes report the same discrepancy. Resetting grace stem
lengths to their provisional defaults does not reproduce the wider width;
stem length alone is therefore not the explanation.

The page pass also moves the acciaccatura slash: Beam::layout sets each final
stem length, calls StemSlash::layout, then recreates the segment shape.
StemSlash::layout derives its vertical position from the stem hook position.
The slash was not reset by the v0.88 probe. A3's affected gap precedes that
grace group. This makes late beam-dependent geometry a targeted hypothesis,
not a proven slash-only diagnosis.

## Change

Before optional system fitting and final optional spacing, finalize beams
belonging to supported before-grace groups. Their internal horizontal positions
are already fixed relative to one main chord, so enclosing measure stretch
does not change their beam span. Beam::layout refreshes stems, slash geometry,
and the owning native segment shape before the planner reads them. The later
page pass remains in place.

The helper requires spacingLayout4, horizontal stretching, an enabled visible
chord-rest segment, a group admitted by buildGraceBeforePlan4, and member
positions matching that group's plan. Unsupported and manually modified
groups stay outside this preparation. The read-only planner is unchanged.
The beamLayout4 toggle still chooses the beam algorithm independently.

Remove the temporary stem-reset diagnostic from tst_spacing. Retain separate
short width messages and all original layout assertions and tolerances.
No new score files or style defaults are introduced.
