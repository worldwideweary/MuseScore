# v0.142: guard slur kerning before system layout

Apply after v0.141. Fix checkpoint: 0548b07.

## Failure and source diagnosis

The native XML reports signal 11 in graceBeforePlan:legacy-beams before the
new undo/redo tests run. The v0.140 side-kerning branch computes
second->pagePos and note->pagePos even when its blocked-side mask is zero.
A note/ledger-line pair can take that kerning branch during grace preparation.
LedgerLine::pagePos directly dereferences chord()->measure()->system(); that
frame may be absent before system collection. This is an unsafe source path
consistent with the abort. The XML has no stack trace, so do not claim a
native crash reproduction or confirmed native fix yet.

## Fix

When no endpoint-side restriction exists, do not query page coordinates at all.
This preserves the pre-v0.140 behavior for ordinary grace contexts.
When a restriction exists, require both measures to belong to the same ready
system, validate visual-staff indices and the second item's physical staff
index, then reject nonfinite ordinates. Failure leaves the caller's output
policy untouched. Do not invent a coordinate origin for a missing system.
This conservatively retains fallback for a restricted pair without a usable
frame; frame-independent source-coordinate adaptation remains future work.

The v0.141 history classifier/update/profiling code is unchanged. Broader
reanchor admission and performance work is paused until this test abort is
resolved. This delivery does not expand v0.140's anchor scope.
