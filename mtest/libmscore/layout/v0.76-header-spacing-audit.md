## Source comparison

spacingplan4.cpp::distance4 already follows the pinned Studio 4.7.5 header
exception sequence: clear the widest header shape, enforce systemHeaderDistance
(or systemHeaderTimeSigDistance), then enforce an absolute 1.5sp gap after
subtracting header right extent and the next segment's left clearance. For the
ordinary visible-header context accepted here, its type/measure checks match
the relevant needsHeaderSpacingExceptions conditions. Unsupported repeat,
above-staff time signature and frame cases are outside this comparison.

getFirstSegmentXPos and our first-segment dispatch both use clefLeftMargin for
header clefs. Studio's default is 0.75sp; Evolution's is 0.8sp. clefKeyDistance
is 0.75sp versus 1.0sp. The two header-to-note distance defaults are identical:
2.5sp without a time signature and 2.0sp after a time signature. The 0.05sp
clef-left difference alone is too small to explain the apparent screenshot gap.
No blanket reduction of header distance or rhythmic spacing is justified yet.

Studio Shape::left returns the negated geometric left edge, as does the typed
projection's left-clearance calculation. Their signs are not a discovered bug.
Evolution Segment::minRight contains some legacy margin adjustments, but the
planner already computes projected extents directly, avoiding those additions.
Actual generated-item shapes/positions and imported effective style values
still need comparison. Screenshot offsets/zoom do not provide exact coordinates.
