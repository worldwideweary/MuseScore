## Runtime test coverage

Both beam algorithms:

1. graceFitting first lays out all six measures together and obtains their
   natural whole-system width. Re-layout at 1.1, 0.55 and 0.35 of that width.
   Require one system at the wide target and multiple systems when narrowed;
   verify all six measures survive, narrowing does not reduce system count,
   each system fits naturally, and its actual justified measure/segment
   positions and widths match the complete typed plan. Verify each grace
   group's applied local positions at every width.
2. graceSqueeze calculates natural and first-positive-pass widths for S1, then
   sets the printable width strictly between them. Require the resulting
   native layout to use the fitting compressed/justified whole-system plan,
   not merely a successful read-only query. Group-local positions remain
   fixed. An impossible zero-width query leaves the caller's plan and native
   geometry unchanged.
3. Both check repeated-layout stability and exact-with-tolerance restoration
   when experimental spacing is turned off. Snapshots retain system membership,
   active segment geometry, fixed offsets, main left space and grace positions;
   cached disabled headers/trailers from earlier line choices are excluded.

Local verification: C++11 debug/release syntax and moc for tst_spacing, XML
music equivalence to the accepted N controls, full rhythmic duration, explicit
beam direction and option values, whitespace and parent patch-application
checks. Full Qt 5.9.9 compilation, tst_spacing and tst_beam are user checks;
these new runtime paths have not been executed locally.
