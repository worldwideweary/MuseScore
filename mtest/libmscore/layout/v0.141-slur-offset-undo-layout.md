# v0.141 WIP: bounded offset layout during undo and redo

Apply after v0.140. WIP implementation checkpoint: c41f38d.

## Problem and resulting behavior

Direct grip offsets already use the bounded slur-offset layout, but undoing
and redoing the exact same offsets still calls the affected-range pipeline.
ChangeProperty::flip restores values/flags through normal setters, which
request range layout; Score::undoRedo previously had no offset-only proof.
That explains why successful direct arrow movement did not imply fast undo.

Inspect the next history entry without executing it. It must be a flat macro
containing only exact ChangeProperty objects without child commands, all on
one unlinked SlurSegment whose root is also unlinked. Allow the four grip
offset properties and whole-segment OFFSET, plus GENERATED bookkeeping. At
least one offset operation is required. Reject subclasses because they can
override execution, nested commands, multiple targets, generated-only macros,
autoplace/direction/anchor changes and every other property/command type.
Flattened same-target offset macros remain eligible.

After normal undo/redo execution, verify the expected history-index movement,
command generation, links and unchanged root anchors/ticks/tracks. Only then
request the existing offset update. Preserve native input/selection restoration,
playlist notification and undo ordering. Clear the proof after update so it
cannot leak into later work. Default spacing does not use this classification.
No command merging, key timer or deferred final layout is introduced.

The existing update validates one master score/no linked parts, one or two
visible pitched staves, one music system/page in Page view, one slur segment,
no layout flags and sufficient vertical page room. Two-staff cross-staff
content remains excluded. All other scopes still take the range path.

## Profiling

Score::undoRedo now opens a timing command only when there is no active
collector, and closes only that owned collector. An existing command's timing
is not reset or closed. Add the undoRedo stage so history work is distinguishable
from direct arrows. Its inclusive time overlaps update/slurOffsetLayout and
must not be added to them. Disabled profiling does not read a clock or
initialize per-thread timing storage.

Accepted replay should show undoRedo and slurOffsetLayout without system/plan
counters. Fallback may contain undoRedo plus system/plan counters. Default
commands retain their normal update path, with timing enabled only on request.
The GUI's later inspector/view work is outside Score::undoRedo's owned timer;
this is not a measurement of total input-to-paint latency.
