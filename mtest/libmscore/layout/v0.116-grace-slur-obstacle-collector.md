# v0.116: read-only combined-grace slur obstacle collection

Implement the first bounded step from the v0.115 source audit. No call from
SlurSegment::layoutSegment yet: rendering and horizontal packing are unchanged.
The new query is buildGraceMergedSlurObstacles4() in gracespacing4.cpp/.h.

## Scope and coordinates

Require an automatic supported first-after-grace-to-target-main slur and
existing complete combined geometry, with both endpoints in one laid-out
system. The validated same-direction, same-track, same-measure group retains
all existing edit, ownership, beam, note and component guards. Other local
before-grace anchors are deliberately outside this collector's scope.

Use the combined plan only to identify members and validate their complete
component context. Read current chord positions when collecting obstacles;
never use the plan's hypothetical target-relative x positions. Convert each
physical component through chord position, grace parent position when present,
segment position and measure position. This matches Slur::slurPos's system-x /
staff-relative-y coordinates. Do not add staff y twice.

Exclude all components of the actual starting grace chord and the ordinary
source owner. Retain all other incoming after-graces, all target before-graces
and the target main chord's own components. Reuse the identified component
adapter, which removes known synthetic spacing bounds and excludes nested
grace components from the target's own footprint. Remove ledger lines as in
Studio getSegmentShape(). Retain intervening notes, accidentals, stems, hooks
and stem slashes admitted by that adapter, including those sharing an
endpoint's musical segment. Preserve each component identity.

No beam-polygon, articulation, text, multi-voice, cross-staff or general slur
obstacle adapter is added. These inputs retain the existing bounded query's
rejection. No clearance inflation, clipping, attachment changes or curve
solver changes occur yet. Validate finite translated bounds. Publish the
complete output only on success; preserve every caller output on rejection.

## Regression coverage

New graceMergedSlurObstacles data rows reuse all three v0.113 paired-slur
fixtures under legacy and modern beam settings. For every slur:

- require every intervening note and visible accidental;
- reject actual start/source-owner and ledger-line components;
- verify exact native physical rectangles transformed through parent chains;
- require only direct item identities, with no synthetic/shared aggregates;
- preserve published horizontal, grace, stem and primary-beam snapshots.

Move a target-owned grace locally and verify only its obstacles move. Move the
whole measure in x/y and verify source-owned after-graces and target-owned
before-graces both translate exactly once. Query calls must not publish
changes. Edited slurs and target stems, plus null input, reject atomically.
Repeated collection must reproduce the same rectangles and identities.

Local validation: C++11 source/test syntax, moc, 70 executions of the exact
collector body with mocked DOM/component producers covering translations,
ledger filtering, deliberately unrelated plan offsets, non-finite coordinates,
null/wrong anchors, missing system, partial component failure and atomic
output preservation; staged whitespace and parent-patch applicability.
Native connector parsing and score-layout mtests cannot run locally. User
must build and run tst_spacing/tst_beam before curve integration.
