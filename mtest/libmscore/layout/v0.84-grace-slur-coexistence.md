# v0.84 WIP: preserve optional spacing with a local grace-to-main slur

First implementation stage from the v0.83 source audit. This changes the
horizontal admission policy only; Evolution's slur direction, endpoints,
Bezier curves and collision renderer are unchanged.

## Bounded allowance

spacingLocalGraceSlur4 requires resolved endpoints from the first before-grace
chord to its own main chord, same score/staff/voice, matching musical tick at
both endpoints, a visible solid slur, autoplace on, no user offset or edited
segment grips and at most one segment. Both zero segments before initial layout
and one segment after layout are valid lifecycle states. The full grace adapter
still validates ordinary pitched staff, note/beam types, offsets, attachments,
voices and the existing before-grace geometry boundary.

commonItemContext4 allows that slur only for items belonging to the explicitly
scoped grace root or a root in the prepared system context. Multiple matching
slurs, unresolved endpoints and all unrelated spans retain rejection. Default
collision queries with no grace context still reject slurred input. Pass the
prepared context through the system planner's main-note admission check too;
otherwise the group would validate but the later main-note check would reject it.

This avoids removing the score-wide slur guard and does not admit ties or other
note spanners. The same grace geometry/padding remains authoritative. The new
positions are published only through the existing spacingLayout4-gated live
adapter; disabling that option retains the legacy algorithm.

## Paired controls

- v0.84-spacing-grace-slurs.mscx: L1-L6 reuse G1-G6's pitches and explicit
  grace beam directions, with an AUTO slur from the first grace to the main.
- v0.84-spacing-grace-slurs-plain.mscx: identical notes/styles/labels without
  those slurs, for isolating horizontal changes from curve appearance.

Both experimental settings are on. A local grace-to-main slur has equal musical
ticks at its ends but distinct resolved chord identities. The XML connectors
identify the starting grace by grace index zero on the return link; do not
invent a nonzero rhythmic duration to distinguish those endpoints.

## Tests and verification

New graceSlurSpacing runs both beam algorithms. It verifies all six loaded
endpoint pairs, the zero rhythmic span, scoped eligibility and default-query
rejection, applied local group positions and whole-system plan positions/widths.
It compares horizontal snapshots against the unslurred counterpart, checks
edited-grip and unresolved-endpoint atomic rejection, saves/reloads to verify
grace identity, then checks repeated layout and spacing-off restoration.

Local verification: C++11 debug/release syntax for the three changed production
sources and tst_spacing, moc generation, XML connectors and paired music/style
checks, whitespace and incremental patch application. A harness runs the actual
eligibility function with controlled inputs for 56 cases covering lifecycle,
endpoint/root ownership, ticks, tracks, score identity, visibility, line type
and editing restrictions. Those inputs are mocks, not native runtime proof.
Full Qt 5.9.9 compilation, tst_spacing and tst_beam remain user checks, including
actual connector resolution and round-trip behavior.
