# v0.92: after-grace baseline controls

This test-only stage establishes the existing after-grace behavior before
adding a target-segment adapter. Production layout and admission guards are
unchanged. Both experimental options are saved on in the comparison scores.

Open these files from mtest/libmscore/layout:

- v0.92-spacing-after-grace-baseline.mscx: one case per system.
- v0.92-spacing-after-grace-baseline-natural.mscx: wide, unstretched overview.

| Case | After-graces belong to | Target at owner's end tick | Detail |
| --- | --- | --- | --- |
| AG1 | Second quarter note | Following half-note chord | One eighth after-grace, stem up |
| AG2 | Second quarter note | Following half-note chord | Four beamed eighth after-graces, F-sharp and D-flat, up |
| AG3 | Second quarter note | Following half-note chord | Four beamed eighth after-graces, forced down |
| AG4 | Final half-note chord | Ending barline | Two beamed after-graces, up |
| AG5 | Second quarter note | Following half rest | Two beamed after-graces, up |
| AG6 | Second quarter note | Half-note chord with before-graces | Two after-graces meet two before-graces |

Every measure is a complete 4/4 measure with quarter, quarter, half regular
onsets. Grace notes have zero rhythmic advance. No slurs, ties, offsets, TAB,
cross-staff notes, tuplets, or simultaneous voices are introduced. Evolution's
after-grace vector uses reverse storage order, so XML chord entries are
written in the reverse of musical order; the native test verifies the resulting
left-to-right pitches explicitly. Beam direction is saved on the Beam itself.

## Native test coverage

graceAfterBaseline runs both files under both beam algorithms. It requires:

- Six measures, three regular onsets each, expected durations and grace counts.
- After-graces retain the correct main-chord parent, segment, track, and tick.
- Correct musical pitch/spelling order, stem direction, finite ordered x positions,
  and a shared beam for multi-note groups.
- The expected following chord, barline, or rest exists at the owner's end tick.
  This validates fixture target semantics; no new target-selection API is added.
- Current before-grace and full-system planners reject after-grace input without
  changing caller outputs or native geometry.
- AG1-AG5 keep their native after-group placement relative to the following
  target when spacingLayout4 toggles on. The original v0.92 whole-measure
  equality assertion was incorrect and is corrected in v0.93: rhythmic spacing
  still acts when the full planner rejects after-graces. AG6 intentionally has
  no target-relative equality assertion because the existing local before-grace
  adapter may change its target's shape despite system-plan fallback.
- Repeated layout is stable; switching spacing off restores the baseline.
- Saving/reloading preserves after-grace ownership, count, pitch/spelling order,
  beam direction, and both style flags.

Local validation: C++11 test syntax and moc generation, XML ownership/order,
durations, and style/break structure. Full Qt runtime mtests must run in the
target build; they have not been run locally.
