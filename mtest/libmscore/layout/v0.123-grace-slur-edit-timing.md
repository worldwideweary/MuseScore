# v0.123: measure held-arrow slur editing

v0.122 still feels slow when an arrow key is held. The attached recording
shows the interaction, but cannot identify CPU cost. Do not treat video
duration as a native layout benchmark or accept this slowdown as necessary.

## Change

Add an opt-in, command-scoped timing diagnostic. No geometry, eligibility,
padding, curve fitting, edit handling, or publication rules change.
`MS_LAYOUT4_PROFILE=1` is read once at process startup; with it unset, the
scopes read no clocks, collect no counters, and produce no diagnostic output.

The arrow-key path calls startEditDrag/editDrag/endEditDrag for every step.
editDrag computes the curve immediately; endEditDrag requests layout, and
Score::endCmd calls update(false). Consequently the same step can incur both
preview work and a layout pass. v0.122 reduced some repeated extraction, but
did not remove this command/layout path.

The header-only diagnostic shares one set of counters across translation
units on each thread. A successful Score::startCmd resets the counters and
starts the command clock. Score::endCmd emits one summary after update and
command completion. Calls made outside a command are not accumulated.

Stages: score update, system collection, system spacing plan, before-grace
plan, after-grace plan implementation, merged plan, merged geometry, merged
beam preparation, slur obstacles, beam-side anchors, curve fitter, and item
context checks. Early returns are counted. Inclusive times contain measured
children; self times subtract them. Do not sum inclusive times. Uninstrumented
work is included in its nearest measured parent's self time, or only in the
command total. Timing itself adds overhead, especially for numerous short
item-context checks; use call counts as well as elapsed times.

## Native reproduction

1. Apply after v0.122, rebuild, and run tst_spacing and tst_beam normally.
2. Close existing instances so the new process receives the environment.
3. Launch the rebuilt executable from a terminal, replacing the placeholder:

   ```sh
   MS_LAYOUT4_PROFILE=1 /path/to/your/37E 2>37E-v0.123-layout-timing.log
   ```

4. Open the same score and select the same slur grip. With experimental
   spacing on, hold one arrow for about one second, then release. Repeat with
   spacing off in the same score. Preserve the same zoom and grip.
5. Send the log and identify which run was first. No new comparison score is
   required. Restart without the environment variable for ordinary use.

Each summary starts with `layout4-profile command=...ms`; each stage uses
`name=calls/inclusive-ms/self-ms`. The command total excludes the later paint
event and OS keyboard-repeat scheduling. If command times are small despite
visible delay, investigate repaint/event backlog next rather than assuming
the measured layout stages caused it.
