## Completed

prepareGraceBeamsForSpacing4 already obtains complete validated merged-grace
geometry: a fresh query when checking an existing prepared beam, or the final
validated output from prepareGraceMergedBeams4 after actual beam preparation.
The immediately following system plan previously rebuilt those same inputs.

Preparation now emits a short-lived vector of ready geometry. It starts empty
on EVERY call, even when experimental preparation is disabled. Before an
ordinary after-grace preparation, a merged-grace beam preparation, or a
before-grace beam layout, the ENTIRE vector is cleared. A beam write can affect
more than its immediate group. Only successful full queries obtained after the
last possible write survive for the next read-only plan.

Each prefix-fitting call owns its own vector. Final placement owns another.
Nothing is reused from a previous fitting attempt or collectSystem call.
The existing longer-lived prepared-beam comparison still makes its fresh full
geometry query; this change does not weaken that invalidation check.

buildSpacingPlan4 accepts the optional validated handoff and uses matching
owner entries while staging merged groups. Missing entries use the original
fresh query. All ordinary-after checks and the remaining system, segment,
projection, collision and spring checks still run. squeezeSpacingPlan4 may
pass the same inputs through its read-only candidate builds; no native
publication occurs until a complete fitting plan succeeds.

The optional-input contract requires complete successful geometry from the
current unchanged DOM. Discard it before any score/geometry input changes.
This is an immediate preparation-to-plan handoff, not a persistent cache.
Calls without it preserve the independent fresh-query path used by tests and
other callers. No beam formulas, spacing rules or fallback gates are changed.

With MS_LAYOUT4_PROFILE=1, planGeometryReuse counts accepted handoff entries.
geometry continues to count full rebuilds. Expected savings depend on later
preparations invalidating earlier entries; do not bypass a write to get hits.

disabled preparation call also discarded old entries. This checks the real
control flow with a mock DOM, not native engraving or timing.

cannot be run in this local environment.

enabled/disabled operation and debug/optimized build metadata. Scoped source
whitespace checks pass. No native performance gain is claimed yet.
