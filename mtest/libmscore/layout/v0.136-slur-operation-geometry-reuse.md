# v0.136: share merged geometry within one slur layout operation

Apply after the corrected v0.135 package (after-v0.133). This delivery also
includes the documentation-only record of the passing v0.135 native mtests
and M1 timing run. No separate patch for that record is needed.

## Completed

The beam-anchor helper and curve-obstacle helper independently called
buildGraceMergedGeometry4 while computing the same slur. Both need the same
complete validation and packing. Slur::layoutSystem and Slur::layout now
install a stack-local GraceMergedSlurQuery4 immediately before calculating
the anchors. The obstacle helper borrows that same query during curve layout.
Its native physical projection still uses current published chord positions.

The first applicable helper performs the complete existing geometry query.
The second may borrow that successful result for the same owner. Each helper
still runs its own slur, anchor, system and visual-edit admission checks.
Failed geometry queries are not memoized. Changing the requested owner builds
fresh geometry. No acceptance gate, packing rule, beam formula or curve rule
is broadened or changed.

The score inputs must remain unchanged during this scope, except for derived
slur direction/segments/curve drawing. The guarded region changes no note,
grace, stem or beam geometry. QScopedValueRollback restores the prior borrowed
pointer on every return, including nested calls. Copying a Slur starts with a
null pointer rather than copying an active query. Direct slurPos calls and
grip previews outside these two layout methods use fresh queries as before.
Nothing is retained across edits, beam preparation or later layout calls.

With profiling enabled, slurGeometryReuse counts successful geometry borrows.
The geometry stage continues to count actual builds. This is a limited reuse
of complete validation, not a cache across all 53 original system queries.
No native timing gain is claimed before measurement.
