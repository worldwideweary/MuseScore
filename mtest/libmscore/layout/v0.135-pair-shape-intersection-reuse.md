## Completed

pairPolicy4 previously rebuilt both native item shapes, translated them into
their respective parent-local positions, and intersected them on every
eligible note/note, note/stem or note/rest component pair. Multiple physical
rectangles can refer to the same items; packing and subsequent projection
also revisit pairs during the same read-only query.

SpacingContextCache4 now memoizes this exact boolean result by ordered item
identity. The cache uses standard pointer hashing. It stores both true and
false outcomes; it does not merge reverse-order queries. The native shape,
translation and intersection expression remains identical on a miss. Existing
scope, item and eligibility checks still run before the lookup, and all padding,
magnification, grace floors and kerning calculations still run per pair.

The existing cache is stack-local to a read-only query, sometimes one complete
system plan. It is destroyed before editing, beam preparation or later layout.
Geometry must remain unchanged for that lifetime. No result persists across
commands; no system plan or beam position is cached by this change.

MS_LAYOUT4_PROFILE=1 now reports pairOverlap for actual native intersection
calculations, excluding memo hits. Timings remain nested and must not be added
to their inclusive parents. Disabled runs retain the existing no-clock path.
