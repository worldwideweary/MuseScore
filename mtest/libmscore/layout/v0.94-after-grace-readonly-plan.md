## New query, no live placement

buildGraceAfterPlan4 returns the owner chord, target segment, musical-order
member x positions, and typed component left/right bounds. Positions are in
TARGET SEGMENT coordinates, not owner-chord coordinates. No positions, shapes,
ownership, measure widths, or styles are written. Failure preserves every
output field. No live layout path calls the query in this increment.

The first scope covers AG1-AG3: one ordinary pitched five-line staff/voice,
unbeamed single-note owner and following chord in the same measure, and one
uniform after-grace group. The target lookup starts at the owner's end tick
and skips segments with no elements on that staff, matching the pinned
appendGraceNotes source. The selected target must be a visible enabled chord-
rest segment containing an ordinary chord in the same voice. A target with
graces is rejected. Barline, rest, and merged targets AG4-AG6 remain outside
this query. Also reject TAB/cross-staff, multiple voices, cue/dotted/chordal
input, tuplets, tremolos, note attachments, ties/slurs, edited note/chord
offsets or stem lengths, and beams extending outside the group.

Packing follows the pinned layoutGraceNotesGroup algorithm: work backward
against the entire accumulated group, then against the following chord's typed
component shape, and apply the same 0.45-spatium terminal safety bound. The
current narrow scope makes that following chord the relevant staff music
shape. Known legacy aggregate spacing rectangles are excluded; unknown shape
ownership still rejects the query.

spacingAfterGracePairPolicy4 grants a separate explicit scope to members of
the owner's after-group and the target chord. It shares the existing padding
and rectangular collision kernel. Default queries, the before-grace scope,
and full system-plan admission are unchanged. No after-grace slur allowance
is added. Shared shape/distance helpers select this scope only when passed an
explicit after-target; the default before-grace path retains its behavior.

## Tests and validation

graceAfterPlan uses both existing v0.92 scores under both beam algorithms. It
checks AG1-AG3 success, correct borrowed pointers/order/terminal bound,
AG4-AG6 transactional rejection, default-query rejection and scoped policy,
independence from stale grace x and unsolved source/target segment x, and
atomic rejection of edited group notes, target notes, and stem lengths.
Full system queries must still reject after-graces. All temporary test edits
are restored before assertions; the final native layout snapshot must match
the initial snapshot exactly. The shared snapshot now includes x/y for all
graces so it can detect writes to after-graces as well as before-graces.

Local validation: C++11 source/test syntax and moc generation; 480 executions
of the exact after-packing body and rectangular kernel with mocked component
shapes/policies; and 480 existing before-packing cases after the shared-helper
refactor. The mock checks verify complete-group clearance, bounds, owner-x
independence, and atomic failure, not native font/DOM rendering. Full Qt
runtime tests remain required in the target build.
