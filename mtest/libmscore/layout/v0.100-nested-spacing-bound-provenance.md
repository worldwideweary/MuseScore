## Cause and correction

spacingElementShape4 resolves the owning Chord::shape recursively. Unpositioned
after-graces can have coincident native aggregate spacing bounds. The resolver
correctly retains their full producer set, one set-bearing record per native
rectangle. afterSourceComponents4 already recognizes those sets from v0.97.

spacingStaffShape4 then reconciles those chord-level results with the native
staff shape. The resolver previously accepted only individual producer records;
set-bearing candidates were treated as unknown. That second pass discarded
valid producer provenance before after-grace substitution could validate it.

Preserve an already resolved aggregate set only when all exactly matching
candidate records are LEGACY_SPACER, have no single item or shared-item list,
carry the same complete set of at least two distinct nonnull producers, and
candidate count equals both native rectangle count and producer-set size.
Normalize pointer order for comparison. A mixture of individual and set-bearing
records remains unsupported. Inconsistent, duplicate, null, mixed, unknown,
missing, or excess provenance remains rejected. Exact rectangle matching and
all downstream ownership/pair-policy validation remain unchanged.

This correction is read-only and confined to the optional geometry adapter.
It does not change native shapes, ownership, grace placement, or score styles.
Keep v0.99 tracing temporarily to confirm actual full-plan application during
native validation; do not advance based solely on a matching final picture.
