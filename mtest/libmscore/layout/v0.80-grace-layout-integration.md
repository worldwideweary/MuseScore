## Change and lifecycle

Chord::layoutPitched now asks the bounded before-grace adapter for a complete
plan after notes have completed layout2. On success, apply member x positions
and replace the legacy group's left extent with max(main left space, new group
extent converted to segment coordinates). The enclosing measure collection
then rebuilds segment shapes before width collection and system fitting.

The existing legacy grace pack runs first on every pass. There is no persistent
new extent or cached plan: a disabled spacingLayout4 or a rejected context
leaves that pass's native positions/width reservation in effect. BeamLayout4
remains independent; both beam algorithms are exercised by the new tests.

This is the first live bounded adapter, not full grace integration into the
Studio system planner. Grace-containing systems retain the native system
spacing path, now using the updated group footprint/reserved space. Existing
full-plan/collision grace rejection remains unchanged and is tested explicitly.
Ordinary five-line, single-voice/single-note before-grace restrictions from
v0.78 still apply. Slurs/attachments, staff moves, TAB, after-graces and mixed
stem directions remain unsupported. No global header/rhythmic constants change.

Grace beam lengths and slash geometry are finalized later by Evolution. The
new applied-position and repeated-layout tests compare the plan against those
post-layout shapes, so the remaining lifecycle assumption is checked rather
than hidden by caching a previous plan. Local harnesses cannot prove this
native beam/shape interaction: the user's complete runtime run is required.
