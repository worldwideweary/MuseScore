Paths above are under src/engraving. StemLayout computes default stem length
from the nominal style length, beam additions, shortening table, intrinsic
magnification, staff overlap, and minimum beam/stem constraints. Evolution's
adapter already implements those major stages; this audit has not established
which input or stage causes the observed pair's difference.

One concrete compatibility difference is anchor magnification:

- Evolution Beam::layoutGraceNotes sets Beam mag to graceNoteMag. The optional
  calculateAnchors4 initializes both solver magnitude and beam width from that
  already-scaled value.
- Studio BeamLayout's nominal beam magnitude excludes the intrinsic grace
  factor for ordinary grace chords. Its drawn width/distance is scaled for
  graces. Before automatic anchor solving, BeamTremoloLayout::setupLData uses
  nominal magnitude for anchor width and applies grace scale separately to
  beam distance. The anchor Y calculation uses half that anchor width.

With graceNoteMag 0.7 and beamWidth 0.5, the anchor widths are 0.35 versus 0.5
staff spatium. Their half-width offsets differ by 0.075sp before rounding to
quarter-space anchor coordinates. This can affect rounding for some inputs,
but does not prove that it explains this D5/E5 pair. No fixed vertical offset
or blanket stem shortening is justified from this finding alone.
