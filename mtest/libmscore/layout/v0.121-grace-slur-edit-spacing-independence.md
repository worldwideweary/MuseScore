# v0.121: manual grace-slur edits preserve modern spacing and curve base

## Verified baseline and reported edit regression

User reports v0.120 native mtests passing. Blue overview
image(20261024-123222).png shows the corrected upper-start alignment. Close-up
image(20261024-123340).png after moving the left grip exposes another issue:
manual slur geometry caused the grace group/system to lose experimental
horizontal spacing and could reset the curve's attachment/base.

The cause is the strict spacingLocalGraceSlur4/spacingMergedGraceSlur4
allowance used by both horizontal collision policy and automatic rendering.
It rejects slur/segment offsets, grip edits and disabled autoplace. Rejecting
that allowance rejects the joint geometry/system plan. Rendering also stopped
using the modern attachment/curve path on a grip edit. Those safeguards were
too broad for visual changes that do not change the musical anchors.

## Separate eligibility and visual edits

Add an explicit allowVisualEdits parameter, default false, to the local and
merged slur eligibility queries. Horizontal component policy requests true:
visual offsets, control-point edits and autoplace state do not invalidate the
existing supported anchor scope. Score/track/tick/ownership/visibility/line-
type/segment-count restrictions remain, as do local one-slur and joint two-
slur limits. Changing musical anchors to an unsupported scope still rejects.

Strict default queries remain available for automatic-only uses. The
identified obstacle collector and beam-anchor helper expose the same explicit
choice. Ordinary unsupported notation, note/stem edits, extra slurs and invalid
shapes retain rejection. No unrelated general slur adapter is added.

## Manual offsets relative to the same automatic curve

Slur::slurPos requests the modern raw beam-side base even when the slur has
visual edits. computeBezier re-queries raw anchors for supported combined
slurs, including direct editing previews where stored points may already be
fitted. Build and fit the automatic cubic WITHOUT user grip or object offsets.
Its initial shoulder rule remains the same legacy rule used in v0.117; the
change makes that base independent of manual offsets.

After fitting, apply the actual start/end offsets. Let controls follow endpoint
movement proportionally along the horizontal span; explicit Bezier offsets
are then added by the existing path builder. Keep all user offsets intact.
A shoulder-drag delta is applied after fitting and accumulated once by the
existing control-offset handling. Use segment ipos rather than pos to exclude
a requested whole-segment translation from automatic collision compensation.

Mark the modern base active for edited curves too, so the legacy collision
pass cannot move the requested user-adjusted result. This does not auto-fit
the edited curve against the user's wishes: fitting applies only to its
unedited base. Users may intentionally move a curve into an obstacle.

The new path remains conditional on experimental spacing, one supported
segment and segment autoplace. Disabling segment autoplace retains its native
manual rendering behavior while preserving horizontal spacing eligibility.
Default-off legacy behavior and unsupported contexts remain unchanged.
