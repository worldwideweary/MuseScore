## General edit path audit

ScoreView::handleArrowKeyPress calls startEditDrag/editDrag/endEditDrag for
every arrow step. SlurTieSegment::editDrag computes the curve immediately;
endEditDrag commits properties and calls triggerLayout. ScoreViewCmdContext
then ends that command, and Score::endCmd calls update(false). Score::update
calls doLayoutRange for the dirty range. System collection performs prefix
fitting and final placement. This path is shared by ordinary and grace slur
edits; the repeated full-system planning cost is not inherently grace-only.

The current timing score still runs 53 combined-grace geometry queries per
step. Moving an ordinary element in a system containing other grace groups
can incur their work as well. The supplied log alone does not isolate a
score containing no grace notes anywhere.

## Ordinary slur admission is a separate limitation

spacingcollision4.cpp::commonChordContext4 scans relevant slurs and accepts
only the explicitly scoped local-before or merged-grace cases. An ordinary
slur anchored to a main chord has neither supported scope and rejects the
plan. buildSpacingPlan4 validates notes before publishing geometry, so this
falls back atomically to native spacing. Visual offset changes do not remove
that ordinary-slur rejection. This checkpoint does not broaden admission.

Consequently, an ordinary slur fixture is useful for the general edit/fallback
path but is insufficient on its own to measure ordinary accepted Studio
spacing. A segment-anchored hairpin does not trigger this slur gate:
commonChordContext4 skips non-slur entries, and it is not a Note spanner.
Use that as a separate ordinary-node control. This source analysis predicts
which paths are exercised; native opening and logs must confirm behavior.
