## Production change

Before system planning, prepare a borrowed context of every supported grace
root. Reuse buildGraceBeforePlan4 for its existing ordinary before-grace
boundary and check each published member x against the newly calculated plan.
Unsupported groups, manual offsets and stale positions reject the whole system
plan without publishing a partial context or modifying native geometry.

Pass that context through typed staff-shape projection and all segment distance
queries. Retain grace component identity/magnification and discard only known
legacy aggregate spacing bounds, as for ordinary chords. Main-to-grace,
grace-to-main and grace-to-grace note floors apply to the relevant pair after
scaled padding. Grace-to-rest also retains Studio's 0.45sp note-padding floor.
Same-beam slash collision permission remains scoped to its group.

Queries without a prepared context retain grace rejection. A context for one
root does not admit another root's grace members or an after-grace. Existing
ordinary context/visibility/ownership guards still apply; this does not admit
cross-staff, slurred, decorated, after-grace or mixed-direction groups.

The system planner now sees the group's true left footprint when calculating
header/previous-note clearance and sees all its components against following
notes and barlines. Existing rhythmic weighting, justification and positive
compression paths operate on the complete segment shape. Group-internal
positions remain fixed during system justification/compression.
