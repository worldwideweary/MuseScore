## Problem and behavior

Every arrow step commits a normal undo command. SlurTieSegment::endEditDrag
requests layout of the spanner's range. The existing update path collects
systems again and reruns horizontal spacing, including unchanged grace packing
and preparation. v0.137 lowers M1's median to 46.152 ms but still runs five
spacing plans and 41 merged-geometry builds per command. This stage changes
the edit invalidation boundary instead of another packing micro-optimization.

For an explicitly classified offset-only slur edit, the initial bounded path
keeps the published horizontal positions and avoids system collection,
measure/chord preparation, prefix fitting and horizontal spacing plans.
It runs native layoutSystemElements, skylines, system staff-distance layout
and the native page pipeline, including final element layout and BSP refresh.
Slur collision queries still inspect grace geometry; they are not a whole-
system spacing solve. No timer, delayed final layout or open undo macro is
introduced. Each arrow step retains its existing undo command and final update.

## Proof of an offset-only edit

SlurSegment captures its anchors, ticks, tracks and command-state generation
at startEditDrag. It requires a clean command state and unlinked slur/segment
in a master score without linked score parts. At commit it requires the same
anchors/timing/tracks/generation, a still-clean state, and only the four grip
offset properties plus whole-segment OFFSET in the recorded property list.
It runs the original edit commit, including property flags and GENERATED,
then tags that known operation only if the command generation still matches.

This does not infer edit type from CmdState::element(), which cannot prove
what changed. A command reset changes the generation and clears the tag.
Any later generic layout request clears the tag, including null-element
requests and direct tick/update-mode requests. Pending work before the commit
also rejects the shortcut. Anchor changes and mixed commands use full layout.
Undo/redo and inspector edits retain their existing general update path.

## Initial bounds and page correctness

The path requires experimental horizontal spacing enabled, one master score
without linked parts or additional movements, one visible pitched staff, one
music system and one page in Page view. Earlier vertical frames may share that
page; additional music systems or later frames reject the path. The edited
segment must be a single segment on that system, and nonempty layout flags
reject the path.

Before rebuilding system elements, restore native pre-justification staff
layout and detach existing system spanner segments for reuse, as System::clear
does, while retaining measures and horizontal geometry. Native page placement
then restores the page's system list. A conservative vertical-space check
includes earlier frames, top/bottom requirements and header/footer extensions.
Insufficient room or nonfinite bounds falls back to complete layout. Thus
vertical growth that might require repagination does not use the shortcut.

This is deliberately not a general multi-staff/multi-system optimization.
It targets the current M1 test shape first. Other scores retain the prior
behavior. N2's independent beam repeat-layout discrepancy remains unresolved;
this checkpoint does not claim to fix its engraving rules.

## Validation

Local C++11 syntax checks cover slur.cpp, layout.cpp, cmd.cpp, score.cpp and
the regenerated-moc tst_spacing.cpp. Debug syntax checks cover slur.cpp and
layout.cpp as well. score.cpp's local syntax setup needs a QSvgRenderer forward
declaration to compensate for the limited local dependency/PCH setup; no
product include or Qt requirement was changed for that check.

An exact-method mock harness exercises 32,768 classification combinations:
style/master/linked-part conditions, pending work before/after capture, linked
objects, changed anchors/ticks/tracks, unknown recorded properties, command
generation changes before/during commit and a second commit without a new
capture. These checks validate the classifier's control flow with a mock DOM;
they do not validate native page layout. Profiler tests cover slurOffsetLayout,
reset behavior, enabled/disabled operation and debug/optimized build metadata.

New native slurOffsetLayout4 rows cover both beam styles on the natural merged-
grace fixture. They exercise all four endpoint/control grips and whole-segment
offset, compare the resulting horizontal/grace/beam geometry, system placement
and slur shapes against complete native layout, and check undo/redo. They also
check cancellation by pending/later generic requests and a command reset.
Existing engraving and repeated-layout tests remain unchanged.

Native compilation, mtests, UI interaction and timing are pending; they cannot
be run locally. This is an experimental bounded WIP, not a measured speed fix.
