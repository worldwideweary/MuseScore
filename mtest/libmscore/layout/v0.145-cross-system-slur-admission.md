# v0.145 WIP: spacing admission independent of rendered slur segments

Apply after v0.144. Initial WIP checkpoint: 111d99d.

## Problem and change

The user confirms v0.144 native mtests pass and grace-endpoint traversal is
better. With systems introduced by narrowing the page, M1 spacing changes
when the slur extends into the following system. The forward after-grace
horizontal admission helper still rejects nsegments > 1. A rendered slur
segment count is not an input to Studio's logical endpoint-side kerning rule.

Remove that count gate from the qualified explicit forward helper. Keep its
score, direction, endpoint identity/order, membership, timing, track, staff-
move, visibility and line-style checks. Spans crossing systems use the native
multi-segment slur renderer. The horizontal adapter still computes side flags
only at actual logical endpoints; it does not treat system-edge fragments as
extra chord attachments.

Remove the same cached-count condition from the local and adjacent merged
pair validators. Their existing anchor identities, same-chord/same-measure
bounds and timing already constrain the musical pair. On return from a split
slur, the old two-segment render state can still be present while horizontal
preparation runs. Rejecting that old count would produce a transient fallback
even though the anchors have returned to the original pair. Preserve visual-
edit checks and all logical specialized curve/obstacle bounds; no curve
formula or general cross-system curve fitter is ported by this change.
