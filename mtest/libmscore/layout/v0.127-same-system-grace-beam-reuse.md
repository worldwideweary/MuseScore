The user reports v0.126 native mtests passing, continued latency, and no

## Source finding and change

collectSystem repeatedly calls systemFittingWidth4 as measures are appended,
then prepares grace beams again for final placement. Earlier groups can
therefore undergo the same beam/packing convergence multiple times in one
collection call. Previous increments only reduced work inside those queries.

Keep a preparation record local to collectSystem. Before reuse, the existing
buildGraceMergedGeometry4 call still fully validates the group and rebuilds
its current projection. Require identical owners/target, bounds, ordered
member identities and x positions, beam object identities, and every source/
target rectangle coordinate and provenance field. Use scalar equality for
rectangle coordinates rather than QRectF's potentially fuzzy equality.
If anything differs, perform the original preparation and replace the record.

prepareGraceMergedBeams4 can optionally return its final validated geometry
on success, including the no-beam branch. Failed preparation leaves that
output untouched. Store the returned geometry after convergence, not its
provisional input. Ordinary after-grace and before-grace handling is unchanged.

The record is destroyed when collectSystem returns. It is never retained
across systems, edits, styles, undo or later layout calls. Style changes cannot
interleave with this synchronous collection call. A fresh validation still
rejects unsupported/manual contexts. This does not defer updates or change
the convergence limit, spacing rules, anchors or fitting algorithms.
