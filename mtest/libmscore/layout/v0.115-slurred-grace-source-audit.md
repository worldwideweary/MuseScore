## Collision coverage: a concrete gap

Evolution SlurSegment::layoutSegment() skips the entire start and end
segments before reading their staff shapes. This avoids collisions against
anchor-owned ledgers and accidentals but also omits other grace members
stored in those segments. Here the after-graces are source-owned, and the
before-graces are target-owned. Both endpoint segments can therefore hold
obstacles between the rendered endpoints while being skipped completely.
The current loop cannot distinguish these members from the actual anchors.

Studio SlurTieLayout::getSegmentShapes()/getSegmentShape() gathers endpoint
segment shapes and removes selected individual items: the starting chord's
own items, text and ledger lines, endpoint articulations and other special
contexts. Other intervening grace notes can remain. addMinClearanceToShapes()
adds 0.4 spatium to intervening note obstacles, 0.2 to articulations, and 0.1
to other items; it treats actual endpoint-owned items separately. This is a
confirmed architectural difference and a plausible contributor to M4. It is
not yet proof that it alone accounts for the visible curve.

## Shape ownership prevents a literal transplant

Studio after-grace geometry is published in its appended segment. Its slur
collector explicitly selects that segment for after-grace anchors.
Evolution still stores after-graces under their musical source chord;
combined spacing uses temporary target projections and publishes x offsets
relative to each grace's own parent. Simply changing the legacy slur's start
segment to the target would lose source-owned obstacles.

Evolution ShapeElement is a rectangle without release-build item identity.
Studio ShapeElement retains an item pointer and filters ownership. Therefore
removing the legacy endpoint-segment skip would also test anchor items and
legacy spacing rectangles, risking large false corrections. Use the existing
identified spacingElementShape4/SpacingShape4 component projection to gather
physical component rectangles, excluding synthetic spacing extents, with
explicit chord ownership and system-coordinate conversion. Check the actual
anchor chord, not all members sharing its parent or musical tick.

## Attachments and curve solver are separate changes

Studio slurPos() scales the default grace anchor clearance with intrinsic
magnification. Its beam-side branch uses stem length, half beam width,
scaled beam clearance and a horizontal beam inset. Evolution uses older
unscaled clearance constants and stem-height branches. Do not flatten these
rules into one global grace-stem or slur offset.

Studio avoidCollisions() divides a sampled clearance curve into left/middle/
right sections, adjusts shoulders and endpoints with different balances,
and allows up to 30 iterations. Evolution computes a curve, tries at most
two collision-height passes and can translate the whole slur vertically.
Matching obstacles alone will not reproduce Studio's curve solver.

The current horizontal substitution occurs during collectSystem(), before
system slur layout. Final page processing also lays out grace beams and
spanners. Any new collector must read final physical component positions
and must not reuse stale temporary projections or modify horizontal packing.
