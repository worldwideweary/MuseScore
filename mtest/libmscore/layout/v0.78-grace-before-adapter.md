# v0.78 WIP: read-only before-grace placement adapter

The user accepted v0.76 compilation/mtests and the matched header control;
v0.77 completed the source audit. This stage implements the first ordinary
before-grace placement plan. It does not install that plan in live layout yet.
That separation is intentional: Evolution's early grace positioning precedes
final beam/stem geometry; the next stage must reserve the new group extent in
horizontal layout and rebuild native shapes without a second-layout shift.

## Implemented

- buildGraceBeforePlan4 reads finalized native shapes and returns member x
  positions plus the group's left extent, relative to the main chord.
- Build backward against the entire accumulated group, then against the main
  chord. Remove the main shape's old grace components and each chord's known
  legacy spacing bound, retaining typed notehead/accidental/ledger/stem/hook/
  slash footprints. Unknown geometry rejects the whole result.
- Apply pinned Studio default grace-to-grace (0.3 score sp) and grace-to-main
  (0.45 score sp) floors after magnification-scaled padding, then Studio's
  terminal bound -(0.45sp + last headWidth/2). Convert segment/main coordinates
  explicitly. These constants are not new editable style fields in this WIP.
- Scope slash collision permission to the same grace beam; other slash pairs
  use normal kerning. The ordinary collision query still rejects all graces;
  the system planner's grace guards remain in place.
- Publish only on complete success; no native positions/shapes/widths change.

Initial context: visible ordinary five-line pitched staff, full-size un-beamed
single-note main chord, before-graces with one normal head each, same voice,
consistent grace stem direction and beam membership, no manual offsets,
articulations, ties/slurs, lyrics, tremolos, tuplets, after-graces or staff moves.
Other voices at the main onset and relevant local segment attachments reject.
System text labels are allowed. TAB and cross-staff graces remain outside scope.

## Tests and visual control

v0.78-spacing-grace-before.mscx has both experimental options enabled, matched
Leland/header styles and six labels:

- G1/G3: ordinary F-D-B-E to C contour, forced up/down stems.
- G2/G4: F-sharp/D-flat/B/E to C, forced up/down stems.
- G5/G6: one grace before the main note, up/down, isolating the terminal gap.

These are controlled examples, not an exact reconstruction of the user's
original score. There are no slurs. At this WIP the score still displays the
existing Evolution positions; do not expect a new on/off visual difference.
The same file provides a stable baseline for Studio comparison and the next
integration stage.

Qt graceBeforePlan runs both beam algorithms, checks source membership,
ordered positions, the final bound, all notehead pair constraints (including
nonadjacent members), independent padding floors and ordinary-query rejection.
It checks no DOM writes, ignores deliberately shifted old grace positions,
and verifies atomic rejection for a note offset, a stemless main and null input.

Local verification: C++11 debug/release syntax checks for both production files
and tst_spacing; moc generation; XML parse/duration/label/style checks; whitespace
check. A small controlled harness executes the actual packing body, actual
rectangular distance function and actual group distance loop for 480 varied
footprint/coordinate cases, including all pair floors, terminal safety, extents
and failure atomicity. Its context/shape inputs are mocks: it does not replace
full Qt 5.9.9 mtests or prove native lifecycle integration. User runs full
compilation, tst_spacing and tst_beam.
