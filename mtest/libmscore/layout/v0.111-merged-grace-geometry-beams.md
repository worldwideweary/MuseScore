## Temporary joint geometry

Add GraceMergedGeometry4 and buildGraceMergedGeometry4. Query the validated
joint plan, stage the incoming owner's own components in its source segment,
and stage the target's own components plus every planned after/before member
in target-segment coordinates. Exclude the old grace footprints and known
legacy aggregate bounds using the existing validated helpers. Preserve every
member's original musical parent. Require complete typed identities and publish
the output only after all source, target and member projections succeed.

This query does not move items, rewrite native shapes, or admit the combined
group into production/system planning. Failed output remains untouched.

## Isolated beam preparation

Add prepareGraceMergedBeams4 as an explicit staging helper. After joint geometry
validation, collect both groups and their distinct beams. Temporarily place each
group at its planned intra-group distances, anchored to that group's original
first member x. Lay out both beams, restore every member x, refresh both native
segment shapes and query the joint projection again. Require unchanged member
identity/order and stable source/target geometry within eight attempts. Compare
rectangles and all provenance metadata; use the same 1e-9 tolerance as existing
after-beam preparation. Groups without beams need no preparation.

The helper changes derived beam/stem geometry, not musical parents or published
grace x positions. If a later iteration fails or does not converge, the caller
must use native relayout before relying on the derived geometry. It does not
promise rollback of beam/stem caches. All member x positions are restored before
every post-layout failure check. Eligibility rejection performs no preparation.

Only tests call this helper in this checkpoint. Existing production preparation,
projection, admission and publication remain unchanged. No rendered spacing or
M2 rule is changed.
