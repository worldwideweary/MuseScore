## General spacing change

buildSpacingPlan4 prepares immutable context inputs, then validates notes,
projects staff components, and computes segment distances without modifying
the score. Those smaller queries previously each started a new eligibility
cache. Share one cache across this entire read-only plan, including ordinary
notes, per-note admission, collision projection, segment distance queries and
the existing separate cross-stem policy scope.

Shape-distance and projection APIs accept an optional caller cache. Standalone
callers retain their local cache. Existing value-based scope keys still clear
entries when grace admission or context changes; cross-stem checks retain
their original null context. All item validity, geometry-dependent pair
policies, shared ownership, padding, collision and fallback checks remain.

The cache contains chord eligibility only. It is destroyed when the plan query
returns, including failures. No plan results, positions or widths are retained
across edits, system collections, squeeze passes or later queries. This stage
targets ordinary notation as well as grace notation; it is not a grace-only
editing shortcut and does not skip system layout.
