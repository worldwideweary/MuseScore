# v0.74: bounded cross-staff spacing milestone

Source baseline: MuseScore 3.7-Evolution, with the pinned Studio 4.7.5 reference.
This records acceptance through implementation/test checkpoint v0.73. It adds
no production changes and requires no new build or visual score.

The user reports tst_spacing/tst_beam passing after v0.73. The comparison score
breaks into F1-F2, F3-F4 and F5-F6 in both Evolution and Studio. No obvious
collision is visible in the supplied captures. These are successful functional
and visual controls for the bounded scope below, not a claim of full Studio
layout parity.

## Behavior covered

- Independent, default-off beamLayout4 and spacingLayout4 score options;
  legacy spacing remains available with spacingLayout4 off.
- Nonmutating placement plans, typed collision geometry, rhythmic spacing,
  minimum widths, fixed offsets outside springs and whole-system justification.
- Bounded automatic cross-staff eighth-note beam streams between ordinary
  visible grand staves, with unambiguous inferred stem sides and stem anchors.
- Alternating staff changes and runs, up to two unmirrored normal notes per
  beam chord, ordinary accidental geometry, held companions and up to two
  complete un-beamed sixteenth-note companion voices.
- Adjacent beam corrections distinguished from nonadjacent beam-neighbor stem
  floors; intervening voice onsets receive no inappropriate fixed correction.
- Multiple supported beam contexts in separate measures of the same system,
  automatic system fitting, regenerated headers and positive compression.
- Full-plan/actual-application checks, repeat stability, atomic rejection and
  restoration to the spacing-off result, under both beam settings.

Earlier ordinary non-cross notation has broader tests; these bounds describe
the cross-staff adapter specifically. Temporary cross-stem geometry remains
conservative. Native within-chord accidental packing and unrelated vertical
layout policies remain Evolution's handling.

## Remaining visible difference: later-system headers

The v0.73 captures suggest extra clef-to-first-note space in Evolution on F3
and F5 compared with Studio. Their interior gaps consequently appear slightly
tighter after system justification. The first system is closer. Screenshot
placement/zoom differences prevent treating this as a precise measured offset;
confirm it using header and first-note coordinates before changing constants.

Evidence: Evolution image(20261023-102851).png / 102901 and Studio 102932 /
102943. Keep v0.73-spacing-cross-staff-fitting.mscx as the reproduction.

Next inspect generated header geometry and spacing at subsequent system starts,
compare effective style values and coordinate allocation with the pinned source,
and add a focused regression if a source/adapter difference is established.
Do not compensate by changing general rhythmic spacing or broadening note cases.

## Deliberately remaining fallbacks and separate work

- Independent cross-staff beams within one measure, cross-barline beams,
  mirrored seconds and larger cross-staff chords.
- Mixed moving companion rhythms, incomplete streams, additional moving
  streams, beamed companions, and cross-staff rest/tuplet/grace/tremolo contexts.
- Unsupported manual overrides, decorations, hidden-staff/frame contexts and
  stronger collision-allowing compression beyond the adapted positive passes.
- The registered centered cross-staff beam-direction/anchor reproduction.
- The earlier R1 rest-placement and tuplet-bracket-policy differences.

These fallbacks preserve the existing Evolution path; passing the bounded
controls does not demonstrate parity for unsupported combinations. No default
style changes, file-format migration or forward-port patch is introduced here.
