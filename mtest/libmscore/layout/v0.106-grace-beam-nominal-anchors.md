# v0.106: nominal anchors for ordinary grace beams

Start from v0.105, whose native tests the user reports passing.

## Evidence and change

The supplied result(20261024-062718).xml records, in staff spaces, the same
read-only solver comparison under both beam modes:

| Input/result | Scaled baseline | Nominal candidate |
|---|---:|---:|
| Anchor width | 0.35 | 0.5 |
| Start anchor Y relative to beam origin | -1.25 | -1.0 |
| End anchor Y relative to beam origin | -1.5 | -1.25 |

Both anchors move toward the up-stem noteheads by 0.25sp, preserving the
slant. This is consistent with the remaining screenshot difference. It is
native evidence for this pair, not a universal fixed shortening amount.
The default stem lengths remain 2.275sp and 2.1sp; this change does not edit
those rules or ordinary quarter-note stems.

Pinned Studio 4.7.5 BeamLayout and BeamTremoloLayout::setupLData separate the
intrinsic grace scale from nominal beam magnitude during anchor solving.
The source paths and verified blobs are recorded in the v0.105 audit.

Select nominal magnitude 1 only for ordinary automatic pitched grace beams:
no cross-staff movement, cue grace/main chord, manual beam/stem edit, or
tremolo; beam magnitude must equal the finite positive intrinsic grace scale.
Reuse the probe's eligibility guard. Other contexts retain their previous
anchor calculation. The existing beamLayout4 caller gate controls rendering;
spacingLayout4 remains independent. Rendered beam thickness and beam distance
remain grace-scaled. No fixed offset or blanket stem shortening is introduced.

The read-only comparison API retains current* as the v0.104 scaled baseline
and separated* as the nominal candidate, now selected by supported production
calls. Its queries still leave score geometry and failed outputs untouched.
