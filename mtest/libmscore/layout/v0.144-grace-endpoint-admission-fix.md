# v0.144: grace endpoints in slur traversal

Apply after v0.143. WIP checkpoint: b4931ce.

## Problem

The v0.143 traversal test assumed Shift+Right jumps between main chords only.
Evolution's native nextChordRest and prevChordRest include grace notes by
default. The test fails at the first unmodeled grace stop in each of its eight
rows. Navigation behavior must remain unchanged.

Independently, the horizontal admission adapter rejects every grace endpoint.
That causes the screenshot transition: modern spacing is available at a main
note, unavailable at its grace note, then available again at the parent.
Pulling backward from the original endpoint has the same problem when the
end first reaches its before-graces.

## Change

Allow qualified endpoints belonging to later before/after-grace groups. Verify
the endpoint's parent is a normal chord and its membership in that parent's
correct before/after vector, matching score/track/tick metadata and no staff
moves for either endpoint or parent. Retain explicit direction, visibility,
solid line, single-segment and first-after-grace start requirements.

For an endpoint in the source owner's own after-group, order it using the
actual after-grace vector: it must occur after the first/start member. These
anchors share a tick, so a positive tick difference alone would wrongly reject
them. A before-grace belonging to the same owner, a grace in an earlier group,
or the start itself remains outside the forward admission.

Adjacent original main-note endpoints retain the established merged-pair
contract. The new grace-ended spans use the existing native slur renderer and
the endpoint-side kerning adapter, not the original pair's specialized curve
or obstacle inputs. This changes no key handling or undo history semantics.
No range-layout performance shortcut is included in this correction.

## Validation

Build an independent musical-order vector for the native regression from
each main chord's before-graces, main chord, and after-graces, in segment
order. Actual Shift+Right commands must visit these pointers, retain a modern
plan whose measure/segment/merged-grace positions match published geometry,
match fresh layout, and restore through undo/redo. Continue the two-slur case.
Then actually Shift+Left from the original endpoint through its before-graces
and the owner's later after-graces; require the same published-plan/fresh-
layout checks and undo restoration. All eight beam/staff/direction rows remain.
The existing adjacent/automatic/frame safety regressions are unchanged.

Local C++11 debug/release syntax checks pass for spacingcollision4.cpp;
regenerated-moc tst_spacing.cpp syntax passes. A standalone harness runs exact
extracted native nextChordRest and prevChordRest functions against an
independent before/main/after ordering over twelve differently sized mock
scores, totaling 798 forward/backward pointer checks. This validates the test
order model with a mock DOM; it is not native engraving execution.
Full application/mtests cannot run locally and remain pending.
