# v0.95: guarded live after-grace packing

The user reports that v0.94 builds and passes mtests. Its plan query remains
read-only; this increment adds a separate local publication step for AG1-AG3.

## Visual targets retained

The close-up comparisons identify two specific differences, which the earlier
overview assessment understated:

- AG2: Evolution's D-flat-to-B grace gap is wider than Studio 4.7.5's.
- AG5: Evolution's first after-grace D is too close to the owning C; Studio
  leaves a better gap. This rest-target case is still unsupported by the new
  adapter and remains outstanding after this increment.

Do not treat passing mtests or a broadly similar overview as visual parity.

## Live step

Chord::layout2 still runs its native after-grace placement first. With
spacingLayout4 enabled, applyGraceAfterPlan4 builds a fresh ordinary after-grace
plan and checks every typed source-chord component against every proposed
grace component in the available native segment interval. It discards only
known legacy aggregate bounds and old grace footprints; unsupported identities
or shared geometry reject publication.

All proposed owner-relative positions must be finite and meet the scoped pair
constraints before any member moves. The conversion is targetSegment.x minus
ownerSegment.x minus owner.x plus plannedTargetRelativeX. After success, refresh
the source segment's native shape. Do not change musical ownership or measure
and segment widths. Failure leaves the native positions intact. Disabling the
style restores native placement on the next layout because that path runs first.

The explicit after-group pair scope gains an includeOwner argument, default
false, used only for this source-clearance check. Default/system and before-
grace query admission remain unchanged. The system planner still rejects
after-graces. This local step uses the existing reserved interval; full typed
target-segment projection, width reservation, and automatic fitting integration
remain the next stage. A cramped interval can therefore retain native packing.

AG4 barline, AG5 rest, and AG6 merged-group targets still reject. No guessed
extra spacing or per-case adjustment is added to approximate the screenshots.

## Tests and comparison files

New copies contain the exact AG1-AG6 musical inputs, with both experimental
styles on and updated titles:

- v0.95-spacing-after-grace-packing.mscx: separate systems.
- v0.95-spacing-after-grace-packing-natural.mscx: compact natural overview.

graceAfterLayout runs both files under both beam algorithms. It provides ample
justified width, requires AG1-AG3's actual positions to match fresh plans after
full layout, verifies idempotence and unchanged measure widths, tests atomic
rejection of a deliberately cramped interval, requires unsupported AG4-AG6
publication to reject without moving anything, and checks repeated layout and
complete spacing-off restoration.

graceAfterBaseline retains the default-page ownership/order/round-trip and
stability checks. Its target-relative native equality assertion now covers
AG4/AG5; AG1-AG3 are intentionally eligible for the new packing and instead
receive the explicit live-plan assertions above. AG6 keeps its previous mixed-
group boundary treatment. The v0.94 read-only tests remain in place.

Local validation: C++11 source/test syntax and moc generation; 36 executions
of the exact publication body with a mocked DOM/query/policy, covering safe
publication, first/last-member clearance failures, unknown source geometry,
query rejection, and known aggregate exclusion; XML checks confirming both
new scores preserve the v0.92 musical inputs and save both styles on. These
checks do not execute native Qt layout mtests.
