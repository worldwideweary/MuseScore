# v0.97: ordinary after-graces enter system spacing

The user reports v0.96 mtests passing. This increment connects the validated
AG1-AG3 target projections to full optional system planning and publication.
It does not add rest, barline, or merged targets. AG5's owning-C-to-after-D gap
remains a specific unresolved visual discrepancy.

## Geometry and policy

Prepare the complete after-grace projection alongside before-grace contexts.
Only after all groups validate does the planner publish its temporary context.
Before-groups still require their existing published positions to validate;
after-groups use target-relative virtual positions and do not require stale
native after-x to match them.

For the affected staff, validate native item/aggregate/shared provenance before
substituting the source and target shapes. Every discarded native rectangle
must belong to the replaced chord or its after-graces; unknown, foreign,
nonfinite, mixed, or malformed ownership rejects the plan. Other segments and
staves retain their existing geometry path. The target projection contains each
grace once, so the usual owning-note-to-target collision calculation reserves
the full interval without keeping a duplicate source footprint.

The native collection stage can have coincident old aggregate bounds before
graces are positioned. Extend the source filter to recognize complete known
legacy aggregate producer sets owned by this chord/group. Reject duplicate or
foreign producers. Do not discard unclassified geometry.

The collision context gains a separate afterMains list. After-grace pair queries
require membership in that validated list; default queries and before-only
contexts still reject them. No after-grace slur allowance is introduced.

## Plan and live publication

SpacingPlan4 retains the target-relative after-group plans through squeezing
and justification. After every measure/segment position is final, convert them
to owner-relative x and refresh each owning segment's native shape. Keep musical
ownership unchanged. Publish directly from a successful complete plan, including
compression, rather than applying an unsqueezed local clearance test afterward.

The existing prefix fitting call now sees supported after-grace geometry as
well. If an unsupported group occurs anywhere in a system, preparation rejects
transactionally and retains the existing fallback/local-packing path. This is
why the new ordinary-only controls are separate from the six-case fallback
controls. Spacing-off behavior remains on the existing native path.

## Tests and validation

graceAfterSystem checks both new three-case files under both beam algorithms:
full-plan admission, actual measure/segment coordinates and widths, actual
target-relative grace positions, read-only positive compression, repeated layout,
and complete spacing-off restoration. The existing graceSqueeze runtime test
also covers AS1 and requires its compressed plan and actual grace publication.

Earlier baseline/query tests now require supported separate systems to succeed
and the mixed natural AG1-AG6 system to continue rejecting atomically. Default
collision queries remain rejected. Existing local-publication, projection,
ownership/order, round-trip, and fallback tests remain active.

Local validation: C++11 source/test syntax and moc generation; 64 executions of
the exact substitution body with mocked DOM/provenance; 10 exact source-filter
aggregate cases; and XML style/duration/group-count checks for the three scores.
These checks do not run full native Qt layout. Native runtime validation,
including final beam-geometry stability, is outstanding.
