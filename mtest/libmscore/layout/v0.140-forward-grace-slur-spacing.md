# v0.140 WIP: preserve modern spacing for a forward grace-slur anchor change

Apply after v0.139. Implementation WIP checkpoint: 03dd6d5.

## Problem and resulting behavior

Shift+Right on the end grip moves the musical endpoint, rather than nudging
its visual offset. In the diagnostic score the end moves from M1's half note
to the next measure's first quarter note. The old horizontal admission only
accepts the original merged grace pair; the new span rejects the modern
spacing plan and the system uses legacy spacing. This produces the wider
note/grace gaps shown in the user's screenshots.

Admit a separately bounded forward span for horizontal spacing. It must start
at its owner's first after-grace chord and end at the first chord/rest segment's
chord on the same track in the immediately following measure. Require explicit
Up/Down direction, visible solid slur, at most one segment, matching scores,
tracks and anchor ticks, and no staff moves. Allow at most one such forward
span per affected chord, in addition to the existing local/merged limits.
Automatic direction, rest/grace endpoints, cross-voice/staff, farther measures,
other ending segments and multiple-segment slurs retain fallback.

This does not broaden spacingMergedGraceSlur4 or its anchor/obstacle adapter.
The extended slur uses native Slur layout; borrowing the old grace pair's
specialized curve inputs would be incorrect. An anchor change still uses the
normal affected-range update. The offset-only classifier and v0.138/v0.139
shortcut bounds are unchanged.

## Studio source audit

Pinned 4.7.5 ChordLayout::checkStartEndSlurs records endpoint sides;
Chord::computeKerningExceptions blocks kerning above a down-stem note when
an up-slur attaches, and below an up-stem note when a down-slur attaches.
HorizontalSpacing::computeNoteKerningType applies that side restriction,
while allowing offset up-stem seconds to kern. It compares the other item's
vertical position with the note's position.

Adapt those rules for only the newly admitted forward span. Require explicit
direction so spacing never depends on stale automatic slur-direction state.
Apply the restriction when the first item is a note and the existing policy
would otherwise allow kerning; keep existing nonkerning/right-edge/collision
rules. Cache the resulting per-chord endpoint-side bits inside the existing
unchanged-DOM query cache; discard with that query. Existing local grace-slur
spacing remains unchanged. An anchor change may therefore have a small,
legitimate spacing effect from endpoint-side kerning; it should not switch
the whole system to legacy spacing.

Local source references: reference/chordlayout-4.7.5.cpp,
reference/chord-dom-4.7.5.cpp and reference/horizontalspacing-4.7.5.cpp, from
the previously pinned 4.7.5 checkout. No new upstream version was substituted.
